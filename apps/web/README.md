# On Record web

The landing page and the app (React, Vite, TypeScript, plain CSS on design tokens). Design notes are in [docs/DESIGN.md](../../docs/DESIGN.md).

## Run it

```bash
npm ci
npm run dev        # http://localhost:5173, proxies /api and /ws to :8000
```

Without the API running, the UI uses the two bundled demo meetings. Force either mode with `?demo=1` or `?demo=0`, or set `VITE_DEMO`.

| Route | What |
|---|---|
| `/` | Landing page: the 3D turntable, the unspool, a live replay of the meeting room, the Ask demo |
| `/meetings` | Meetings, each a tape strip of who spoke when |
| `/m/:id` | Meeting room: speaker lanes, transcript, what Gemma 4 extracted |
| `/commitments`, `/decisions`, `/people`, `/graph` | Memory across meetings |

`npm run build` type-checks and builds to `dist/`; `npm run lint` runs oxlint.

## 3D assets

The turntable, the microphone and the stills in `public/landing/` are generated by Blender scripts. To rebuild them (Blender 5, Node and `cwebp` on the path):

```bash
scripts/blender/build.sh            # the GLB and its contact shadow
scripts/blender/build.sh --render   # also the Cycles stills, a few minutes on a laptop GPU
```

The hero turns `Platter`, `ArmPivot` and `ArmLift` from the GLB, and paints the record's grooves and label at runtime from `src/api/demo/fixtures.json`. `src/landing/turntable/meta.json` (written by the build) tells it where the spindle, pivot and stylus are.
